# PLAN-0007：增加对称榨取与反制互动

| 状态 | 完成时间 |
|---|---|
| 已完成 | 2026-09-04 |

## 问题与最终结果

原互动只有 `透/日`，提示与结算分别判断反透，首次使用和失败目标还依赖 Handler 回滚冷却。现在 `透/日/榨` 由一个 Alconna matcher 接入：正值主动透、非正值主动榨，动作不匹配或 xnn 透触发反制时，目标按自己的世界反透或反榨一次。

core 一次固定实际动作、行动者、液体和接收者，提示与结算复用同一结果。正值被榨产生“脱氧核糖核酸”，非正值被榨产生“妹汁”；数量始终记在实际获得液体者名下，并继续复用原无类型日累计和“注入量”查询。

## 关键改动

| 模块或路径 | 最终改动 |
|---|---|
| `impart/core.py` | 增加互动动作、参与方、液体、反制原因和纯解析结果，覆盖双方世界与 xnn 分支并保证最多反制一次 |
| `impart/app.py`、`infra/cooldown.py` | 发起者首次使用时只创建并返回；缺失目标按默认 10cm 创建后继续；冷却只检查不预占，在有效目标和固定结果后才记录；结算按领域结果写入实际接收者 |
| `bot/matchers.py` | 使用 Bracket Header 解析 `透/日/榨`，继续要求群友/管理/群主并接受多个 At |
| `bot/handlers/interaction.py` | 群友只取首个 At，管理和群主忽略 At；统一正常、反透与反榨提示和报告，找不到目标使用“喵喵喵?”文案，管理候选排除发起者 |
| `bot/handlers/shared.py` | 提取多个玩法 Handler 共用的新用户创建文案 |
| `__init__.py`、`README.md`、`docs/architecture/overview.md` | 同步命令、累计语义、初始化、冷却和分层职责 |

## 已知缺口与后续事项

- 本计划不实现正负世界转换，也不决定转换后如何处理累计量。
- 透与榨继续共用一份无类型日累计；公开查询仍使用原“注入量”称呼。
- 实际回归优先保证 OneBot V11；其他 Adapter 只维持通用接入设计，不增加事件级 fixture。
