## 背景

以当前工作树 `feature@bef376b` 为核查基线。用户要求继续多阶挑战设计，先考虑一阶完成后的能力，并提前做好必要的数据结构；本轮只整理计划与自检，未授权实施或提交。

旧远端 `ji-ge` 的 `dev@28d4faf` 在 Memory Bank TASK001/005/006 中提出正负各5阶、称号绑定能力、掉阶失去能力。原始高阶数值属于占位方案，不能直接采纳。相关原文已保存在本地 scratch，本计划自包含已确认规则，不依赖被忽略的快照才能实施。

本切片实现可表达多阶的最小状态与规则，生产先启用一阶，并实现一阶个人基础增减×2。用户确认目标是加快养成，重新评估奖励幅度后明确选择两倍，D-003已定案。二阶进入门槛初步为300cm；305cm完成、胜率系数0.70、失败回退20～30cm及「鉄壁の巨擘／虚空の眼」仍保留为讨论稿，不注册进生产规则。三至五阶、通用技能/Buff/成就框架均不在本次范围。

用户新增的一阶双目标统一PK由 [PLAN-0017](PLAN-0017-dual-target-pk.md) 独立跟进，依赖本计划的阶级与倍率；多人份额、胜率变化次数和目标策略均已确认，但仍作为独立实施单元，不混入本计划的单挑×2和状态结构。

## 技术路线

### 1. 最小阶级结构

- `challenge_tier: int` 表示当前世界中仍持有的已完成阶级：0为无称号，1为持有一阶；不是正在挑战的阶数、完成次数或历史最高阶。
- 替换 `challenge_completed`，删除持久化的 `is_challenging`。正负世界继续由长度符号决定，不保存正负两套历史、加成开关或能力来源。
- core 使用轻量的内部阶级数值规则：进入门槛、完成目标、挑战胜率及恢复系数、本阶固定惩罚；按阶级顺序查找，不增加配置文件、管理器或热更新机制。生产规则只配置一阶：25→30、0.8、5cm；现有称号与试炼名称仍由Handler呈现，二阶启用时再统一接入阶级文案。
- 下一阶为 `challenge_tier + 1`。下一阶存在且 `entry <= abs(length) < target` 时处于挑战中；最高已配置阶没有下一阶，不再挑战。
- 例：tier=0、26cm是在挑战一阶；tier=1、26cm是持有一阶。未来二阶启用后，tier=1、301cm是在挑战二阶，仍持有一阶奖励。
- 正常提交的阶级与长度必须相容；高于下一阶完成目标却尚未结算完成属于未归一化状态，不能长期留在数据库，再指望只读查询补写。

### 2. 一阶个人基础增减×2（D-003已确认）

2026-09-05，用户明确奖励目标为加快养成，考虑过幅度后决定采用×2，不采用×1.5。此前确认的作用范围和按个人结算原则不变，包括PK失败损失同样翻倍；不改变PK赢面，不改为只增加收益的单向奖励。

| 路径 | 采用谁的倍率 | 范围 |
|---|---|---|
| 打胶／挖矿 | 自己结算前的阶级 | 本人的基础长度／深度增长 |
| 被嗦／舔 | 目标结算前的阶级 | 目标得到的基础增长；不使用执行者倍率，也不把双方倍率相乘 |
| PK获胜 | 获胜者结算前的阶级 | 其获得的基础长度／深度 |
| PK失败 | 失败者结算前的阶级 | 其损失的基础长度／深度 |

- `challenge_tier >= 1` 时个人倍率为2，否则为1。进入更高阶挑战保留一阶奖励；不推断二阶会变成4倍，也不每完成一次重复叠乘。
- 当前通关的这一局按旧阶级计算，下一次才享受新奖励；当前掉阶这一局仍用旧阶级倍率，之后失效。
- 不翻倍已有总长度、胜率及其每局±0.01变化、冷却、挑战阈值与系数、固定失败/掉称号惩罚、互动毫升数、雌堕减5cm或夺舍平分结果。
- 保留 `get_random_num()` 的分布、调用次数和位置约束。PK先分配原始基数：胜者 `num/2`、败者 `-num`，再分别乘个人倍率；不要把全局随机数先乘2。
- 分半后不要提前舍入再乘倍率。先完成基础算术、个人倍率与方向，再对最终长度使用现有三位小数和世界锁；报告基础变化应从 before/base 的实际差值得出。例如基数0.101、有称号胜者得到0.101，而不是先把0.0505舍入成0.051后再得到0.102。
- 通用数据库写方法不自动加倍率，避免污染固定惩罚、夺舍和上游导入。

### 3. 用前后状态识别挑战变化，保留现有胜率语义

普通路径使用 `before → 基础增减后的 base → 挑战处理后的 final`。在同一次纯结算中判断当前持有阶级及下一阶，再以一个事务提交 final。

| 前后变化 | 阶级和固定惩罚 | 胜率处理 |
|---|---|---|
| 从进入门槛以下跨入挑战区间 | 保留已持有阶级，产生开始事件 | 乘本阶系数一次 |
| 从进入门槛以下一次跨过完成目标 | 直接提升至本次挑战阶，产生成功事件；保留超出目标的数值 | 不先应用再恢复挑战系数 |
| 前后仍在同一挑战区间 | 不重复开始 | 不重复乘除 |
| 挑战中达到完成目标 | 提升至本次挑战阶，产生成功事件 | 解除本阶减益一次 |
| 挑战中跌破进入门槛 | 退出本阶，保留仍满足条件的低阶称号，施加本阶固定失败惩罚 | 解除本阶减益一次 |
| 已持有称号跌破该阶保级门槛 | 失去该阶，施加该阶固定惩罚；掉阶后恢复增长不能直接找回历史称号 | 没有挑战减益就不额外恢复胜率 |

保级门槛沿用进入门槛，等于门槛不失败/掉阶，等于目标即成功；保留越过目标的增长量，不截断到目标。不以本轮数值下不会发生的“二阶普通失败一路罚到一阶”引入连锁惩罚框架。

存储胜率继续采用现有约定：挑战中已含本阶减益。PK仍根据发起者该值判定，胜者减0.01、败者加0.01并沿用现有舍入；之后才按挑战进入/退出施加或解除系数。例：0.5进入一阶变0.4，挑战内一次失败变0.41，若本局退出则恢复为0.5125，而不是改成基础胜率0.51。此次不引入双方归一化，不另存基础胜率或原始胜率备份。

一阶退出继续沿用当前乘以1.25的恢复路径，不改写为除以0.8。二者数学等价但浮点表示不同，下一局三位小数舍入可能相差0.001；例如0.39恢复后再减0.01，乘法路径得到0.478，除法路径得到0.477。保留乘法并增加该序列的回归用例，不引入Decimal或新胜率公式。

core 派生函数读取状态不会修改概率或制造事件；进入/成功/失败/掉阶事件来自本次前后变化。查询、重复读取、门禁拒绝和启动不重复乘除或补播。事件只作为当前结果传给 Handler，携带必要的对应阶级信息；不增加数据库通知标记或通用事件总线。

### 4. 夺舍边界（已确认）

- 负值且 `challenge_tier >= 1` 即拥有一阶解锁的夺舍；发起者正在更高阶挑战时仍允许使用。目标必须正值、长度严格短于发起者深度，且目标不能处于由阶级与长度推导出的挑战区间。
- 仍按目标原长度的一半向上保留三位小数；不使用基础增减倍率。先算半长再判门槛，保留49.999→25和49.998→24.999的边界。
- 发起者退出旧世界挑战时解除旧阶减益，不算通关或失败，不追加挑战/旧称号罚退。其他情况下不调整其胜率；不改变当日或历史注入量。
- 发起者转正后，按半长满足的最高已配置保级门槛直接授予阶级，允许绕过对应正值试炼；不再触发一次“进入高阶挑战”的减益或广播。不记录通过挑战还是通过夺舍获阶。
- 目标按既有称号失去规则后处理；固定惩罚不翻倍，双方最终长度可以不同。高阶跌落后保留仍满足条件的低阶称号，不简单把所有进度清零。
- 用二阶临时规则验证两个用户确认的例子：负值302cm、持有一阶并挑战二阶，夺舍280cm目标后转正140cm、持有一阶且解除旧减益；负值700cm夺舍640cm目标，半长320cm直接持有正值二阶。临时规则只服务核心验证，不代表二阶生产参数已定稿。
- 当前负值一阶成功的独立At通知方式继续保留，内容如何合并为一阶能力说明见 D-004；一阶→二阶不重复通知已经拥有的一阶能力。不重新设计现有夺舍成功文案，不补XNN专属提示。

### 5. 原子写入、查询及接入

- PK、成长、夺舍与互动保持共用现有 application 锁，消息、资料查询、绘图和动画继续在锁外；不增加多进程协调。
- 将自成长与目标成长的“更新状态→修改长度→再更新状态”收敛为一次成长结算事务。core负责纯计算，DataManager负责在同一个 Session 读取与写回长度、胜率、阶级；不用循环调用现有独立提交方法。沿用 `settle_pk()`、`settle_possession()` 的事务模式，不新增统一工作流框架。
- 场景、首At、世界、自目标、初始化、既有成长挑战门禁及冷却顺序保持。门禁只读检查，不触发历史补结算；被拒绝不抽成长随机数、不占用新的冷却。新用户仍10cm、0.5胜率、tier=0。
- 查询与排行榜的新用户初始化沿用现有行为，仅同步新字段默认值；正常查询不修改阶级或胜率，本轮不另行重构查询和排行榜流程。
- 所有状态映射及 `UserQueryData` 换成 `challenge_tier`，通过 `QueryOutcome` 传到回复层。查询按实际阶级及世界选称号，不只看绝对长度；保持当前当天/完整历史一致快照、日期升序与图表约定。
- 成长和PK回复使用实际基础增减量；固定惩罚仍单独说明。现有结果类型按需补充对应阶级信息即可，不为每种倍率单建Handler。
- 用户新增挑战完成后的额外能力提示需求，取代此前“只在主回复里说明、不增加独立加成提示”的安排。确认正常结算保留原挑战文案，随后复用 `_finish_game_reply()` 为实际通关者发送一条独立At能力通知；负值翻倍与原夺舍说明合并，不再各发一条。完整文案与触发细节见已确认的D-004。
- 帮助同步已实现的能力；通知也只列当前已经落地的能力。PLAN-0016单独完成时只说明×2和已有夺舍，PLAN-0017完成后再扩展同一条通知的双目标PK说明，不提前宣传尚未实现的功能，不增加运行时功能开关或技能注册框架。
- 互动毫升结算不加倍率。XNN雌堕仍限定其原规则，只是用户状态映射变为tier；不得改变 PLAN-0015 的开始快照、最终形态、收量归属或独立转换行为。
- 数据库异常时相关状态共同回滚，但现有进程内冷却仍沿用原失败语义；发送失败不回滚、不重放已提交结果，不为通知持久化额外状态。

### 6. Schema与上游导入

`UserData` 与 `UserGameState` 使用 `challenge_tier` 整数，ORM默认0，移除两个旧字段；更新 `_to_game_state()`、`_apply_game_state()`、查询投影和全新 v1 初始 migration。三个业务表、Ref编码、namespace、日期记录和现有数据库后端边界不变，不添加阶级历史表、倍率列或额外schema版本兼容链。

上游 `nonebot_plugin_impart` 的导入仍是独立承诺：源库只读、标准LocalStore路径、三个目标表任一非空则整体跳过、全部记录一个目标事务写入。旧字段只在导入适配中读取，不能在新的运行模型中保留兼容属性。字段缺失或旧标记与长度不一致时，按已确认的 D-001 规范化，不能删掉字段后原样复制旧字典。

#### D-001 · 已确认：旧库导入只规范阶级和胜率，不补罚长度

2026-09-05，用户确认采用一次无播报的状态规范化：不补扣失败或掉称号惩罚，不修改源长度（原有零值→-0.001例外不变），已经正确应用的挑战减益不重复计算。

旧库可能保留与长度暂时不一致的标记；现有 `tests/units/legacy_import_test.py::test_imports_complete_legacy_snapshot_once` 包含深度8.25cm却保留完成标记的记录。新结构应消除这种不一致，不能把它继续解释成持有一阶。

1. 读取旧胜率及旧标记；旧 `is_challenging=True` 时识别其胜率已含旧一阶0.8系数。沿用旧列缺失默认值。
2. 本轮新库只有一阶：绝对长度达到30，或旧完成标记为真且绝对长度仍至少25，赋tier=1；其余赋tier=0。不根据旧库高长度凭空授予尚未启用的二阶。
3. 根据新tier和长度判断新状态所需的减益：旧、新状态都处于一阶挑战，或都不处于挑战时，直接保留原胜率；仅旧状态在挑战时解除一次0.8，仅新状态在挑战时应用一次0.8。避免把已正确减益的0.4变成0.32，也避免不必要的浮点往返。

例如：26.5cm、旧挑战中、胜率0.4，导入后仍tier=0且胜率0.4；同长度但旧标记未进入、胜率0.5，则导入为挑战中对应的0.4；深度8.25cm却带旧完成标记，清为tier=0、深度保持8.25，不再额外罚5。转换后的完整状态在原有导入事务内写入，不补发挑战、称号或能力消息。

## 已确认事项

### D-004 · 已确认：一阶通关后的额外能力通知

用户要求在挑战完成时增加类似深渊试炼的额外提示，并确认沿用当前“先完成原结算回复，再独立真实At通关者”的顺序，将旧负值夺舍提示扩成完整的一阶能力提示。

确认的触发边界：

- 正常通关由 `challenge_tier=0` 变为1时，对该成员发送一次；正负世界均适用。不是账号终生只发一次，掉阶后重新通关可以再次提示。
- PK对手通关也At对手，不只通知发起者；双目标PK中多人通关时，按发起者、目标顺序为每个实际通关者各发一条，每人本轮不重复。
- 持续持有一阶、后续升高阶、查询、启动和旧库导入不补播一阶通知；本次提示针对通关，夺舍直接授阶不另发这条通关提示。
- 从本局结算结果取得通关成员及世界，不为通知重新读取可能已被并发操作改变的状态。沿用不持锁发送、失败不回滚或重放的边界，不新增“通知过”字段、历史表或后台重试。

PLAN-0016与0017都完成后的联合文案如下，`@用户` 表示真实At消息段，不是写死的文字：

正值：

> @用户 你感到一股神性的力量正涌入体内...
> 你的任何基础长度变动将翻倍！
> PK现在最多可以指定两个目标了！

负值：

> @用户 你感到深渊的禁忌力量正涌入体内...
> 你的任何基础深度变动将翻倍！
> PK现在最多可以指定两个目标了！
> 现在可以使用指令「夺舍」了！

2026-09-05，用户指定正值开头增加“一股”，加成句采用“你的任何基础长度变动将翻倍！”，负值按已要求的对称风格对应为“你的任何基础深度变动将翻倍！”。这是文案修改，不扩大已确认的数值作用范围。

“最多两个”保留只At一个用户的单挑；“任何基础长度／深度变动”仍只指既定基础增减，包含PK失败损失，不包括胜率、固定惩罚、毫升数或夺舍平分。只有PLAN-0016落地时，保留“你的任何基础长度／深度变动将翻倍！”而省略双目标PK一行；负值仍保留夺舍句。后续PLAN-0017扩展同一通知，不再叠发第二条相同起因的解锁消息。

上述文案与通知细节已经用户整体认可。一阶×2、阶级结构与已确认的导入/夺舍规则不因此重开；不新增独立的能力通知框架。
