# PLAN-0006：为负值世界补齐挑战

| 状态 | 完成时间 |
|---|---|
| 已完成 | 2026-09-04 |

## 问题与最终结果

原挑战状态机、成长门禁、PK 状态文案和完成称号只覆盖正值世界，开扣与舔经过 25cm 深度时不会进入挑战，负值 PK 也只输出基础结果。现在正负世界统一按 `abs(length)` 比较 25/30 边界：正值继续使用“登神长阶”，负值使用“深渊试炼 / 深渊挑战 / 深淵の主 / 被深渊拒绝了”，失败和失去称号的 5cm 惩罚都朝零方向移动。

挑战者真实禁用本世界成长命令：正值不能打胶或嗦，负值不能开扣或舔，挑战中的目标也不能被嗦或舔。挑战门禁在冷却和成长随机数之前执行，被拒绝时不记录冷却、不调用 `get_random_num()`；不活跃惩罚仍保持原有行为。

## 关键改动

| 模块或路径 | 最终改动 |
|---|---|
| `impart/core.py` | 使用绝对量级评估正负挑战，按符号确定失败惩罚方向；负值跨过 25cm 可触发挑战，`length <= -30` 分类为深渊称号 |
| `impart/app.py`、`infra/data_manager.py` | 增加发起者/目标两类挑战拒绝结果；目标成长按发起者优先检查门禁，并通过只读挑战标记避免无关发起者被静默更新；有效路径再进入冷却和随机成长 |
| `bot/handlers/game.py` | 开扣使用“扣深了”、打胶使用“导长了”；补齐开扣、舔、负值 PK 双方状态和查询文案，并保留正值原挑战文案结构 |
| `__init__.py` | 帮助提示统一为“长度或深度超过25时会触发神秘任务” |
| architecture 与测试 | 同步正负挑战稳定语义；以少量参数化和聚合测试覆盖状态机、门禁副作用、负值成长触发、PK 文案、称号和元数据 |

## 验证结果

| 成功标准 | 证据或结果 |
|---|---|
| 正负挑战边界与惩罚完全对称 | 参数化验证正负 25/30、挑战成功/失败、失去称号及朝零 5cm 惩罚 |
| 开扣和舔能够触发负值挑战 | application 测试确认深度跨过 25cm 后写入挑战标记并把胜率乘以 `0.8` |
| 挑战命令真实禁用且无结算资源消耗 | application 测试覆盖正负发起者和目标门禁，确认长度、冷却及 `get_random_num()` 均不变化 |
| 负值 PK 与查询文案完整 | Handler 聚合测试覆盖深渊试炼、挑战成败、被深渊拒绝、深淵の主和最终胜率 |
| 正值有意变更受控 | 正值只新增嗦的发起者门禁，并把自身成长增量文案改为“导长了”；原 PK 基础结果和挑战文案继续通过回归测试 |
| 项目质量门 | 101 项 pytest、Ruff lint、格式检查、BasedPyright、sdist/wheel 构建和 `git diff --check` 全部通过 |

## 已知缺口与后续事项

- 按维护者要求保留“超过25cm/30cm”文案，即使数值比较包含等号。
- 本轮不实现零点钳制、世界转换限制或实际损失修正；PK 仍可能跨过零点。
- PK 的双方长度、胜率和挑战状态仍由多个独立数据库提交更新，本轮不改事务边界。
- 首次进入 NoneBot 插件市场前仍把数据库视为全新 v1，不增加迁移或兼容分支。
