# PLAN-0005：让 PK 按正负世界结算

| 状态 | 完成时间 |
|---|---|
| 已完成 | 2026-09-03 |

## 问题与最终结果

目标成长已经区分长度与深度世界，但原 `pk/对决` 允许跨世界目标，并始终按正值方向更新长度。现在 PK 会在用户初始化之后读取双方长度：双方同为正值时完整保留原结算，双方同为负值时反转长度方向，使胜者加深、败者变浅；跨世界时在不活跃惩罚、冷却和游戏随机之前拒绝。

## 关键改动

| 模块或路径 | 最终改动 |
|---|---|
| `impart/app.py` | 增加 `WORLD_MISMATCH` 和本局 `GrowthMode`；按 `length > 0`、`length <= 0` 检查同世界，并用方向系数镜像负值长度写入 |
| `bot/handlers/game.py` | 按发起者世界生成跨世界提示；正值文案原样保留，负值使用“小学”“加深/变浅”和“深暗压迫”，且不追加挑战或跨零状态文案 |
| application 与 Handler 测试 | 聚合覆盖跨世界无副作用、正值回归、负值双方胜负方向、两类跨世界提示和精确回复 |
| README、插件元数据与 architecture | 同步同世界目标要求和正负结算语义 |

## 验证结果

| 成功标准 | 证据或结果 |
|---|---|
| 正值 PK 不退化 | 固定随机下的胜负、胜率、双方长度和原“阴影笼罩”回复通过回归断言 |
| 负值 PK 方向正确 | 发起者胜负两条路径分别验证胜者加深、败者变浅，并验证“深暗压迫”完整文案 |
| 跨世界拒绝无游戏副作用 | 正负两个发起方向均返回类型化 outcome；不执行惩罚、冷却、胜负随机或成长随机，不修改长度 |
| 既有命令边界保持 | 无 At、自目标、首次初始化和多个 At 只取第一个继续由现有测试覆盖 |
| 项目质量门 | 90 项 pytest、Ruff lint、格式检查、BasedPyright、sdist/wheel 构建和 `git diff --check` 全部通过 |

## 已知缺口与后续事项

- 本轮按维护者要求不实现 `0.01/-0.01` 零点锁定、实际损失修正或跨零状态机调整，结算仍可能跨零；负值基础回复继续按本局开始时的深度模式生成，不增加专用提示。
- 胜率仍只使用发起者当前值，并按胜者 `-0.01`、败者 `+0.01` 更新；归一化、阻尼、爆冷倍率和 xnn 修正继续延后。
- 不增加 `击剑`、`磨豆腐/磨`、负值挑战、榨取、事务化结算或 PK 模块拆分。
